# Электронный журнал преподавателя (PHP + SQLite)

Веб-приложение для ведения журнала занятий преподавателя. Три роли:
**администратор** (полный доступ), **ученик** (информация о себе),
**родитель** (информация о всех своих детях).

Стек: чистый PHP 8.1+ (без фреймворка), PDO/SQLite, Tailwind CSS + Vite (сборка).

## Авторизация

Два вида учётных записей:

- **Все роли (администратор, ученики, родители)** входят через **единый портал**
  `auth.nayanovaacademy.ru` (проект `auth-web`). Пароли хранятся только там;
  журнал проверяет сессию через общую куку `auth_session` на
  `auth.nayanovaacademy.ru/api/check.php` (server-side cURL, результат
  кэшируется в локальной сессии ~5 минут). Привязка к журналу — по
  логину (совпадает с логином на портале). Родители создаются в админ-панели
  портала (раздел «Родители») и синхронизируются в журнал как зеркало.
  Если SSO-пользователь вошёл, но локальной записи нет — показывается
  сообщение о недоступности.

Своей страницы входа у журнала нет: неавторизованного `Auth::requireLogin()`
отправляет прямо на портал (`/index.php?page=login&redirect=<исходный URL>`),
после успешного входа пользователь возвращается на исходную страницу.
Маршрут `/login` остался только как лендинг «не привязана к журналу».
Выход SSO-пользователя чистит общую сессию портала и возвращает на журнал.

Зеркало родителей обновляется мгновенно: любое изменение в разделе
«Родители» на портале отправляет сервер-к-сервер уведомление на
`/api/internal/parents-sync` журнала (только с доверенных IP), журнал
сразу пересинхронизирует `ParentService`. Остальные зеркала
(классы/студенты) обновляются при открытии соответствующих разделов.

## Структура

```
public/        Webroot (сюда указывает nginx root)
src/           PHP: роутер, контроллеры, сервисы, БД
db/            app.db (SQLite, вне webroot) + migration.sql
templates/     HTML-шаблоны
assets-src/    Исходники Tailwind/Vite (сборка на Windows-ПК)
runtime/       Логи, временные файлы
pass.md        Учётные данные первого администратора (НЕ коммитить)
```

## Учётные данные

Администратор и ученики авторизуются через единый портал
`auth.nayanovaacademy.ru` (логины/пароли создаются в админ-панели auth-web).
Локальные пароли в журнале имеют только родители (задаются в разделе
«Учётные» при создании родителя или импортом из CSV).

## Локальная разработка (Windows)

Требования: PHP 8.1+, Node 20+.

1. Сборка ассетов (один раз, затем после изменений в `assets-src`):

```
cd assets-src
npm install
npm run build          # компилирует CSS/JS в public/assets
```

2. Запуск dev-сервера:

```
php -S 127.0.0.1:8090 -t public public/index.php
```

(Также подойдёт `php -S 127.0.0.1:8090 public/index.php`.)

3. Открыть http://127.0.0.1:8090/ и войти под администратором.

База `db/app.db` создаётся автоматически при первом запросе (схема из
`db/migration.sql`). Для чистой переинициализации удалите `db/app.db`.

## Деплой на Ubuntu-сервер

### Автоматический деплой (deploy.ps1)

Скрипт `deploy.ps1` собирает ассеты (Vite) на этом Windows-ПК и синхронизирует
приложение на сервер по SSH (tar по каналу ssh). Пользовательские данные на
сервере (`db/` — SQLite БД, `runtime/` — логи) сохраняются при каждом деплое;
код и `db/migration.sql` обновляются.

1. Настройте `.env` (скопируйте из комментариев в файле):
   ```
   DEPLOY_SSH_HOST=...
   DEPLOY_SSH_PORT=22
   DEPLOY_SSH_USER=root
   DEPLOY_SSH_KEY=../ssh-private.key
   DEPLOY_REMOTE_PATH=/var/www/j.nayanovaacademy.ru
   ```

2. Запуск:
   ```
   .\deploy.ps1            # сборка ассетов + деплой
   .\deploy.ps1 -SkipBuild # только деплой (если ассеты уже собраны)
   .\deploy.ps1 -DryRun    # показать команды без выполнения
   ```

3. После деплоя убедитесь, что nginx-конфиг указывает root на
   `${DEPLOY_REMOTE_PATH}/public`, а права на `db/` и `runtime/`
   принадлежат `www-data` (скрипт выставляет это автоматически).

### Вручную

Исходники собираются/копируются с Windows-ПК на сервер.

1. Скопировать проект в защищённую папку, например:
   `/var/www/j.nayanovaacademy.ru/`
   (внутри — `public/`, `src/`, `db/`, `templates/`, `runtime/` и т.д.)

2. Webroot — `.../public`, как в nginx-конфиге.

3. Права: PHP должен иметь право записи в `db/` и `runtime/`:
```
sudo mkdir -p /var/www/j.nayanovaacademy.ru/db /var/www/j.nayanovaacademy.ru/runtime
sudo chown -R www-data:www-data /var/www/j.nayanovaacademy.ru/db /var/www/j.nayanovaacademy.ru/runtime
sudo chmod 775 /var/www/j.nayanovaacademy.ru/db /var/www/j.nayanovaacademy.ru/runtime
```

4. nginx-конфиг (см. файл `j.nayanovaacademy.ru` в корне проекта):
   - `root /var/www/j.nayanovaacademy.ru/public;`
   - `location / { try_files $uri $uri/ /index.php?$query_string; }`
   - PHP 8.1 через PHP-FPM.
   НЕ кладите `src/`, `db/`, `templates/`, `pass.md` внутрь `public/`.

5. Проверить конфиг и перезапустить nginx:
   ```
   nginx -t && systemctl reload nginx
   ```

6. Рекомендации по безопасности:
   В `php.ini` для php-fpm отключите вывод ошибок в интерфейс:
   ```
   display_errors = Off
   log_errors = On
   error_log = /var/log/php-fpm/error.log
   ```

7. Защита `pass.md`: не загружайте этот файл на сервер в webroot и
   не коммитьте в публичный репозиторий.

## Классы и студенты

Классы и студенты больше не создаются и не редактируются в журнале.
Единый источник — портал авторизации `auth.nayanovaacademy.ru`:
- классы — админ-раздел «Группы»;
- студенты — это пользователи портала, закреплённые за группами (разделы
  «Пользователи» и «Группы»); ФИО берётся из `display_name`.
- родители — админ-раздел «Родители» портала (учётка + ФИО + привязка детей,
  `api/public_parents.php`); журнал держит только read-only зеркало.

Журнал держится в актуальном состоянии автоматически (при открытии разделов
«Классы»/«Студенты»/журнала и родительского кабинета) и по кнопке
«Синхронизировать с порталом». Поле `external_id` в таблицах `classes`
(id группы), `students` (id пользователя) и `parents` (id профиля родителя)
связывает локальные записи с auth-web.
